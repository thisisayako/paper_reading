# 論文リーディング

## 研究者情報

- 社会人大学院生（修士課程）
- 修士論文のテーマ：KAKENデータを用いたアカデミアにおける男女の生産性格差とその要因の分析

## 目的

修士論文の執筆に必要な論文を読解し、研究上の知見・論点・示唆を蓄積すること。

## ファイル構成

| ファイル・フォルダ | 役割 |
|---|---|
| `論文要約/` | 要約mdの正本。所見はここに書く |
| `論文要約/WebDB用/` | WebDB論文で使う分の要約md |
| `論文要約/テンプレート.md` | 新規作成時に複製する見出し構成 |
| `要約キュー.md` | 処理台帳。どのPDFが未処理かを見る索引。1論文1行 |
| `処理ログ.md` | 保管用。過去の実行ログと、2026-08-09以前のキュー備考の逐語。通常は読まない |
| `PDF/` | 直下＝未処理。`PDF/処理済み/`＝処理済み |
| `scripts/doi2bib.py` | DOIからBibTeXを取得する。`### BibTeX`を空にしないために使う |
| `scripts/backfill_bibtex.py` | 空のBibTeXをまとめて埋める。`--apply`で書き換え |
| `scripts/check_bibtex.py` | 空のBibTeXと年の相違を検査する。書き換えはしない |
| `CLAUDE.md` | Claude Codeへの口頭依頼の対応表 |
| `.claude/settings.json` | SessionStartフック。開始時に`check_bibtex.py`を走らせる |
| `夜間バッチ指示.md` | Claude Desktopのスケジュール済みタスクに貼る本文。中身は本ファイルへのポインタだけ |

要約のファイル名は`出版年_第一著者_短いタイトル.md`とする（例：`2024_Yamada_Gender-gap-in-academia.md`）。年は誌面の巻号年とし、オンライン先行公開年とは合わせない。

## 作業手順

論文はDOIで渡すことを基本とし、DOIから本文が読めない場合はPDFをアップロードする。DOIから本文全文にアクセスできない場合は、アブストラクト等の部分情報で代用せず、必ずPDFのアップロードを依頼する。

要約作業は次の順序で一連の作業として実施し、都度の許可確認を挟まず自動で進める。

1. 論文を読み、`論文要約/`にMarkdown要約を作成する。`### BibTeX`は`python3 scripts/doi2bib.py <DOI>`の出力を貼る（後述）
2. `要約キュー.md`の該当行の状態を「完了」に更新し、要約ファイル名を記入する。メモ欄は1行に収める（所見の正本は要約md）
3. 処理済みのPDFを`PDF/処理済み/`へ移動する
4. 実行結果を`処理ログ.md`の末尾に追記し、`要約キュー.md`の「直近の申し送り」を上書きする

## 夜間バッチの手順

Claude Desktopのスケジュール済みタスクから夜間に実行される。タスク本文（`夜間バッチ指示.md`）はこの節を指すだけなので、手順を変えるときはこの節を直せばよく、タスク本文は書き換えなくてよい。

以下でパスはすべて`/Users/ayako/Claude/Projects/paper_reading/`からの相対。

PDFフォルダ駆動で動く。`PDF/`直下に置かれたPDFはすべて要約対象で、特定の文献リストに載っているかは関係ない。`要約キュー.md`は処理台帳として使う。

1. 本ファイルに加えて次の2つを読み、粒度と形式を把握する。`処理ログ.md`は読まない（過去の申し送りが要るときだけ末尾を部分読みする）
   - `論文要約/テンプレート.md`（見出し構成）
   - `論文要約/WebDB用/2018_Hechtman_NIH-funding-longevity-by-gender.md`（詳しさ・分析粒度・記述形式の基準。この水準に合わせる。ただし本ファイルの記載と食い違う場合は本ファイルを優先する）
2. `PDF/`直下の全PDFを一覧し（`処理済み/`とそのサブフォルダは対象外）、`要約キュー.md`と突き合わせる
   - キューに行があるPDF → その行の状態に従う（「完了」なら手順3dの移動のみ確認）
   - キューに行がないPDF → キュー末尾に行を追加する（文献・DOIはPDF本文から取得、状態＝未着手）
   - 未処理のPDFが1本もなければ何もせず終了する
3. 状態が「未着手」でPDFが存在する行を、キューの上から順に処理する。1本ごとに次のaからdを行う
   - a. PDFをReadで全文読む（20ページずつ分割）。アブストラクト等の部分情報やWeb検索結果で本文の代用をしない。図表が主要な証拠を担う場合は`pdftoppm`でPNGにレンダリングして目視し、本文が印字した数値と図が整合するかを確認する
   - b. 同じ論文の要約mdが`論文要約/`（`WebDB用/`を含む）に既にあるかDOI・タイトル・著者で照合する
     - ない場合：本ファイルの方針・粒度・テンプレート構成に従い`論文要約/出版年_第一著者_短いタイトル.md`を新規作成する。保存先は`論文要約/`直下とし、`WebDB用/`へは置かない
     - ある場合：既存の本文は一切変更せず、ファイル末尾に`## 追記（実行日付・バッチ）`を追加して差分のみ書く（既存要約にない結果・数値・限界・示唆、および相違点。相違があればどちらが原文と一致するか明記）。差分がなければ「追記事項なし（原文と照合済み）」と1行記す。追記部分にも本ファイルの書式を適用する（既存本文の書式は直さない）
     - どちらの場合も、キューのメモ欄の特記事項には必ず対応する
   - c. `要約キュー.md`の該当行の状態を「完了」（追記なら「完了（追記）」）に更新し、要約ファイル名を`論文要約/`からの相対パスで記入する。メモ欄は1行に収め、後で参照するかを判断できる手がかり（主題・修論との接続・設計上の最大の弱点）にとどめる。数値と原文の不整合の逐語は要約md側に書き、キューには書かない
   - d. 処理済みPDFを`PDF/処理済み/`（なければ作成）へ移動する
4. セッション容量が許す限り次の未着手PDFへ進む。処理を終えるとき
   - `処理ログ.md`の末尾に、実行日時・処理した論文・残数・特記事項を追記する
   - `要約キュー.md`の「直近の申し送り」節を上書きする（追記ではなく上書き。履歴は`処理ログ.md`が持つ）
   - `要約キュー.md`の「未登録PDF」節から、今回登録・処理した分を削除する

BibTeXについては、夜間バッチの実行環境（Claude Desktop）からは doi.org と api.crossref.org へ到達できない。プロキシが`Tunnel connection failed: 403 Forbidden`を返す（2026-08-10に確認）。したがってバッチでは次のようにする。

- `python3 scripts/doi2bib.py <DOI>`は毎回試す。制限が外れていれば取得できる
- 失敗したら`### BibTeX`に「取得できず（コマンドとエラーの逐語）」と書き、コードブロックは空のまま残す。手で組み立てて埋めない
- 実行の最後に`python3 scripts/check_bibtex.py`を走らせ、その出力を`処理ログ.md`の追記に含める
- 埋められる空が1件でもあれば、バッチの最終報告の冒頭に「★BibTeXが空の要約N件。Claude Codeで`python3 scripts/backfill_bibtex.py --apply`を実行して埋めること」と書く。ユーザーがこの1行を見て次の作業を判断する

空のまま残った分は、ネットワークに到達できる環境（Claude Code）で後から一括で埋める。`python3 scripts/backfill_bibtex.py`が差分を表示し、`--apply`を付けると書き換える。対象は「取得できず」の注記があるか`@`エントリを持たない要約に限られ、本文には触れない。

バッチ固有の制約は次のとおり。文体・書式・粒度は後続の「論文要約の基本方針」と「論文要約の構成と粒度」に従う。

- 品質最優先。粒度を落として処理本数を稼がない。容量が不足しそうなら本数を減らす（残りは次回の実行で継続される）
- 変更してよいファイル：新規の要約md、既存要約への末尾追記（それ以外の本文の書き換えは禁止。ただし空の`### BibTeX`を埋めるのは可）、`要約キュー.md`、`処理ログ.md`、`PDF/`内のファイル移動のみ。`scripts/`は実行のみで変更しない。README・テンプレート・他プロジェクトのファイルは変更しない。PDFの削除・リネームはしない（移動のみ）
- 太字を使わないルールは要約mdだけでなく`要約キュー.md`・`処理ログ.md`にも適用する。回帰係数に付す有意水準のアスタリスク（例：0.082\*\*\*）は太字ではないので原典どおりの個数を保つ
- スプレッドシートへの転記は行わない（2026-08-07に廃止）
- git操作をしない。メール送信・外部投稿をしない

## 論文要約の基本方針

- 丁寧語を使わず、文末は簡潔な体言止めとする。体言止めが難しい場合は「である調」とする
- Wordなどの文書ファイルへコピーしやすい、簡潔で統一された体裁とする
- 正確性と実用性を最優先する
- ユーザーを気持ちよくするためのお世辞を言わない
- 最高の回答に必要な情報が不足している場合、回答の生成前に、些細な点も含めて必ず質問する
- 内容への確信度が90%以上の場合のみ回答し、それ未満の場合は「分からない」と明記する
- 英語の文書を渡された場合は、英語で内容を検討したうえで回答する
- 倫理に関する助言は必要最小限にとどめる
- 論文に記載された内容と、要約者による推論・批判的検討を明確に区別する
- 数値、サンプル数、分析対象、期間、変数、推定方法、図表番号などを可能な限り原文と照合する。原文で確認できない値は「未確認」と明記し、もっともらしい値で穴埋めしない
- 太字を使わない。アスタリスク2個による強調記法を要約中で一切使わない。強調が必要な箇所は語順・文構造で示す（見出し、箇条書き、表は従来どおり使用してよい）
- 統計手法や指標は名称を列挙するだけでなく、その結果が何を意味するかを簡潔に説明する
- 「有意差なし」を「差がないことの証明」と扱わず、検出力、追跡期間、標本選択などを考慮する
- 論文の情報量や重要性に応じて分量は調整するが、重要な分析結果や留保を短文化のために省略しない

## 論文要約の構成と粒度

見出し構成は`論文要約/テンプレート.md`に従う。ファイル全体の構成は次のとおり。

```
# 論文タイトル
## 書誌情報（著者、出版年、掲載誌（巻号・ページ含む）、DOI・URL、読了日、キーワード）
### BibTeX
## 背景・目的
## 方法
## 結果・考察
### 全体の結果・考察
### 図表または分析単位ごとの小見出し
## 主張の限界・残された課題
### 著者が記載した限界
### 要約者による追加の検討
## 貢献・採録理由
### 論文に記載された貢献
### 要約者による採録理由の推論
## 修士論文への示唆
```

各セクションに書く内容は以下のとおり。

- 書誌情報：著者、出版年、掲載誌（巻号・ページを誌名に続けて記載）、DOI・URL、読了日、キーワード、BibTeX
  - BibTeXは`python3 scripts/doi2bib.py <DOI>`で取得し、出力をそのまま`### BibTeX`へ貼る。空のままにしない
  - 取得できたBibTeXの`year`がPDFの出版年と食い違うことがある（doi.orgが先行公開年を返すため）。食い違う場合はPDFの値に直し、その旨を書誌情報に1行記す
  - 取得できない場合は「取得できず（理由）」と書き、コードブロックは空のまま残す。書誌情報から手で組み立てて埋めない。DOIを持たない和文誌はPDFの記載どおりに手で書く
  - 引用キーは刊行年（誌面の巻号年）に揃える。doi.orgがアクセント記号を落としたキーを返すことがある（例：Liénard → `Li_nard_2018`）。その場合はファイル名の綴りに合わせて直し、理由を1行記す
- 背景・目的：研究の背景、先行研究上の位置づけ、研究上のギャップ、中心的な問い、仮説、アウトカムの意味
- 方法：使用データ、分析対象、対象期間、サンプル数、主要変数と指標の定義、研究デザイン、推定方法、比較群、感度分析。研究デザインを再現できる程度に記載し、論文に応じて箇条書き項目を追加してよい
- 結果・考察：冒頭に`### 全体の結果・考察`を置き、その後に主要な図表または分析単位ごとの小見出しを設ける。図表が複数ない論文でも、主要な分析単位ごとに小見出しを切る
  - 全体の結果・考察には、(1) 主要な結果を分析単位を横断して統合した要旨、(2) 結果間の整合・不整合、およびどの結果が中心的な主張を支えどれが補助的かの位置づけ、(3) 全体を通じた著者の解釈、(4) 全体を通じた要約者の解釈と注意点を記す。個々の図表の詳細は後続の小見出しに置き、ここでは繰り返さない。この節を読めば結果の全体像が把握できることを基準とする
  - 各小見出しでは結果と考察を分けて記載する。結果には図表が検証する内容、主要な数値・効果量・信頼区間・P値、統計的有意性と実質的な差の大きさを書き、考察には著者の解釈と、要約者による解釈・注意点を書く。図表番号や分析単位が追える粒度を優先する
- 主張の限界・残された課題：論文に記載された主要な限界に加え、明記されていない課題も検討する。因果推論上の問題、測定上の問題、外的妥当性、頑健性検証、代替説明などの観点から整理し、論文記載の限界と要約者の追加指摘を小見出しで区別する
- 貢献・採録理由：既存研究との差分と学術的貢献を整理する。新規性のある問い、データ、指標、方法、結果、理論的・実務的含意などを特定し、どのような差分・貢献が採録につながったと考えられるかを検討する。採録理由が要約者の推論である場合はその旨を明記する
- 修士論文への示唆：KAKENデータを用いた男女の生産性格差研究に応用できる研究仮説、変数、分析単位、推定方法、研究デザイン、注意すべきバイアスを具体的に記載する

詳しさ・分析粒度・記述形式の基準は`論文要約/WebDB用/2018_Hechtman_NIH-funding-longevity-by-gender.md`とする。ただし太字不使用と`### 全体の結果・考察`の設置は本ファイルの記載を優先する（基準ファイルはこの2点の改訂前に作成されたもの）。
